# 마일스톤 기호 사전

이 저장소는 작업 단위를 `R2`, `N1`, `U8` 같은 **짧은 기호**로 부른다. 커밋 메시지·설계 문서·git 태그·
에이전트 지시서가 전부 이 기호를 쓰는데, 정의는 여러 문서에 흩어져 있었다. **이 문서가 그 정본 대조표다.**

정본은 여전히 각 설계 문서다. 여기 있는 건 *어느 기호가 무엇을 가리키고 지금 어떤 상태인가*를
한 화면에서 보기 위한 색인이다. 설명이 어긋나면 설계 문서 쪽이 맞다.

---

## 1. 읽는 법

```
R2
│└─ 그 트랙 안의 순번. 대체로 의존 순서이지 일정은 아니다.
└── 트랙 문자. 무엇에 관한 작업인가.
```

- **트랙끼리는 대체로 독립**이다. 번호가 작다고 먼저 해야 하는 건 아니다.
  단 트랙 안에서는 번호 순서가 대체로 의존 순서다(`R2` 없이 `R3` 을 못 한다).
- **끝났으면 git 태그** `milestone/<기호>` 를 단다(예: `milestone/R2`).
- 트랙이 통째로 끝나면 `project(VERSION)` 의 minor 를 올린다. 코드에서는 `EF_VERSION_STRING` 으로 보인다.

### ⚠️ 이 기호는 저장소 안에서만 쓴다

외부에 공개하는 글과 복습 문서에는 **이 기호를 쓰지 않는다.** 독자는 이 저장소를
볼 수 없으므로 `N2` 라고 쓰면 확인할 방법이 없다. 글에는 뜻이 드러나는 말로 푼다 —
"스폰을 확정 입력 경로로만 일어나게 하는 일" 처럼.

## 3. 트랙별 마일스톤

### R — 렌더링

| 기호 | 무엇 | 상태 |
|---|---|---|
| R0 | `EngineRender` 타깃 분리 + DX11 링크, `IWindow`/`IRenderer`/`RenderContext` 골격 | ✅ |
| R1 | `Win32Window` + 메시지 펌프 (빈 창이 뜨고 X로 닫힌다) | ✅ |
| R2 | Device / SwapChain / RTV + `BeginFrame`·`Present`, HARDWARE→WARP 폴백 | ✅ |
| R3 | 런타임 셰이더 컴파일 + Dynamic VB + 배칭 Draw (쿼드 하나) | ✅ |
| R4 | `Camera`(ortho) + ViewProj 상수버퍼 (월드 XZ → 화면) | ✅ |
| R5 | `Renderable` + `RenderSystem` + `View<Transform, Renderable>` | ✅ |
| R6 | **I1과 합류** — 키 입력이 서버 확정을 거쳐 화면 속 엔티티를 움직인다 | ✅ |
| R7 | `PreviousTransform` + alpha 보간 (50Hz인데 부드럽게) | · |

> **R6이 이 트랙의 핵심**이다. 새 이동 시스템을 만드는 게 아니라 **기존 lockstep 경로를 화면에 잇는 것**이고,
> 그래야 `클라 입력 → 서버 확정 → InputFrame 릴레이 → 클라 적용 → 렌더`가 한 번에 눈으로 검증된다.

### N — 결정론 스폰

| 기호 | 무엇 | 상태 |
|---|---|---|
| N1 | 스냅샷이 `EntityManager` 상태(version / free list / next index)를 나르게 | ✅ |
| N2 | 스폰·디스폰을 **확정 입력 경로에서만** 일어나게 (SessionEvent) | ✅ |
| N3 | 클라 예측 / 롤백 — **정말 필요한지부터 재고** (중간 미래) | · |
| N4 | 대규모 월드 비용 — 영역별 해시, 스냅샷 분할, 관심 영역 (중간 미래) | · |
| N4.1 | `ComputeHash()`에 `EntityManager` 상태 포함 (부분 resync의 전제) | ✅ |
| N4.2 | 해시 분해표(엔티티·풀별·월드) + 양쪽 tick별 기록 | ✅ |
| N4.3 | 부분 resync 데이터 계층 — 분해표 실은 `ResyncRequest`, `PartialSnapshot` 와이어·생성·적용, 풀 선택 함수 | ✅ |
| N4.4 | 동기화 시스템 연결 — 서버 부분 응답, 클라가 서버 tick에서 갈아끼우고 즉시 검증, 실패 시 전체 스냅샷 폴백 | · |

> lockstep이므로 스폰은 원래 **복제할 필요가 없다** — 모두가 같은 입력으로 같은 시뮬을 돌리니 각자 스폰하면 된다.
> 다만 그러려면 엔티티 id 할당까지 양쪽이 같아야 하고, 그 전제가 깨져 있던 것을 N1이 고쳤다.
> 남은 문제는 "누가 접속했다"가 입력이 아니라는 것이었다. N2는 서버가 그 사건을 tick 하나에 못 박아
> `InputFrame`에 실어 보내게 해서 풀었다(`SessionEvent`). 이제 건설·스폰 작업(G 트랙)을 시작할 수 있다.

## 4. M1~M7 — 이건 트랙이 아니다

`M1`~`M7` 은 트랙 문자가 아니라 **결정론 입력 lockstep 설계 문서 안의 단계 번호**다
([deterministic-input-lockstep.md](../design/deterministic-input-lockstep.md)). 그 문서 하나를 완성하는 과정을 쪼갠 것이고,
**전부 완료됐다.** 상세 흐름은 [입력 lockstep 설계](../design/deterministic-input-lockstep.md)를 참고한다.

| 기호 | 무엇 | 상태 |
|---|---|---|
| M1 | 결정론 이동 원시 | ✅ |
| M2 | 서버 확정 + reliable 릴레이 | ✅ |
| M3 | 클라 로컬 시뮬레이션 | ✅ |
| M4 | 클럭 추정 + 입력 지연 + 이중화 | ✅ |
| M5 | 정리 | ✅ |
| M6 | 결정론 수렴 테스트 | ✅ |
| M7 | 문서 | ✅ |

`M` 을 트랙 문자로 착각하지 않도록 주의한다. 새 트랙을 만들 때 `M` 은 피하는 편이 낫다.

## 5. 알려진 표기 문제

고치면 좋지만 아직 안 고친 것들. 여기 적어 두는 이유는, 문서에만 적힌 규칙은 결국 깨지기 때문이다.

1. **`S1` 이 두 뜻으로 쓰인다** (트랙 S의 JSON 라이터 / 중간 미래의 세이브). 위 §3 참조.
2. **`M` 이 트랙 문자처럼 보인다.** 실제로는 설계 문서 내부 단계 번호다.
3. **완료 표시가 두 곳에 있다** — git 태그(`milestone/*`)와 로드맵의 `✅`. 한쪽만 갱신되면 어긋난다.
   실제로 `R1` 과 `U3` 이 **태그는 있는데 로드맵 표에 ✅ 가 없는** 상태로 한동안 남아 있었다(지금은 맞춰 뒀다).
   다시 어긋나서 판단이 필요하면 **태그가 사실에 가깝다** — 태그는 실제로 그 작업을 끝낸 커밋에 붙기 때문이다.
   마일스톤을 끝낼 때 태그·로드맵 표·이 문서의 표를 함께 갱신할 것.
